# もっちーもちもち の個人サイト

星空をテーマにした6ページの静的サイトと、PC上で使うビジュアルエディターです。HTML・CSS・JavaScriptだけで表示でき、外部ライブラリ、有料API、データベース、ログイン機能は使いません。

## 最初に開く

Windowsで **`start-editor.cmd` をダブルクリック**し、表示されたURLをブラウザで開きます。

- サイト：<http://127.0.0.1:4173/mochimochi-site/>
- 編集画面：<http://127.0.0.1:4173/mochimochi-site/editor/>

起動したウィンドウは編集中、そのままにしてください。終了は `Ctrl+C` です。PCに導入済みのNode.jsを使用します。新しいソフトやパッケージのインストールは不要です。

通常のページは `index.html` を直接開いても基本表示できますが、JSON配置の読み込みと編集には上記ローカルサーバーを使用してください。

## 画面を見ながら編集する

1. 左上の「ページ」でHOMEを選びます。標準ページをPC幅1200px・スマホ幅390pxで読み込み、編集可能なパーツへ変換します。
2. 画面上のパーツをクリックするか、左のレイヤー一覧から選択します。
3. ドラッグで移動、右下の青いハンドルでサイズ変更できます。細かな調整は右側のX・Y・幅・高さで行います。
4. 「見出し」「テキスト」「画像」「リンク」「メニュー」「装飾」でパーツを追加します。画像ファイルをキャンバスにドロップしても追加できます。
5. 右側で文字・フォント・文字色・サイズ・背景色・角丸・枠線・リンク先などを変更します。「複製」「削除」「前面」「背面」もここにあります。
6. 「グリッド吸着」をONにすると8px単位で動きます。選択中のパーツは矢印キーで1px、Shift＋矢印で10px移動します。
7. 「戻す」または `Ctrl+Z` で操作を取り消します。`Ctrl+Shift+Z` はやり直しです。最大50操作を保持します。
8. 「PC」「スマホ」を切り替え、両方の位置・サイズを確認してください。**位置・サイズ・非表示は画面サイズ別、文字の内容や基本デザインは共通**です。
9. 「閲覧プレビュー」で選択枠を消し、リンクを確認できます。リンクは確認用に新しいタブで開きます。
10. 「JSONを書き出す」で `layout.json` を保存します。

PNG・JPEG・WebP・GIFに対応しています。1画像5MB以下。PNGは初期状態で「ドットをくっきり表示」がONです。写真などはOFFにしてください。画像はJSONに埋め込まれるため、別ファイルのアップロード漏れを防げます。読み込み速度のため、画像はなるべく小さくし、写真はWebP/JPEGをおすすめします。

フォントはOSに入っているゴシック・明朝・等幅・ラウンドを使用します。端末にないフォントは代替フォントになります。

### テーマ・背景

「星空」「紙とインク」「ガーデン」「ポップ」のテーマを切り替えられます。色、背景画像、角丸などはその後個別に調整できます。元のクジラやドット絵は削除・差し替えできます。ドット絵専用のエディターではありません。

ページ下部まで置きたいときは「ページの高さ」を増やします。キャンバス外のパーツは公開時に切れるため、PCとスマホ両方を確認してください。自由配置のため、文字を長くした際のパーツ同士の重なりまでは自動で解消しません。

### ページの追加・削除

左上の「追加」でページを作成します。追加ページにはホームへ戻るリンクを作り、編集済みページの下部にも新ページへのリンクを追加します。配置は自由に変更できます。標準ページのメニューにも自動でリンクが加わります。

追加ページのURLは `page.html?page=page-…` です。URLはリンクパーツの設定で確認できます。ページ削除時には対応するメニューリンクも削除します。HOMEは必須ページとして残ります。

### 保存・復元

- 編集途中の内容は、このブラウザのローカルストレージにも一時保存します。再起動すると前回の下書きを復元します。
- **確実なバックアップはJSON書き出しです。** 画像が多いとブラウザの一時保存容量を超えます。その場合は画面下部に通知します。
- 別のPCへ移す、以前の版へ戻す場合は「JSONを開く」を使います。30MB以下のJSONに対応します。
- 「標準デザインに戻す」は選択ページだけを作り直します。「戻す」で復元できます。
- 公開済みJSONを読み直す場合も「JSONを開く」で `data/layout.json` を選択します。下書きがある場合、公開データより下書きを優先します。
- 読み込んだページの内容は編集用のスナップショットです。通常の文章はエディターで更新します。一方、「活動データ」のパーツは次項のデータファイルを引き続き使用します。

## お知らせ・作品・SNSの更新

| 内容 | 編集するファイル |
| --- | --- |
| SNS URL・標準プロフィール・初期画像 | `data/site.js` |
| お知らせ | `data/news.js` |
| ギャラリー作品 | `data/gallery.js` |
| ゲーム | `data/games.js` |
| 商品 | `data/shop.js` |
| ビジュアル編集結果 | `data/layout.json` |
| 画像ファイルの保存先 | `assets/images/` |
| 初期テーマの共通色 | `assets/css/style.css` 冒頭の `:root` |

ファイルをVS Codeなどで開き、文字列の引用符と項目間のカンマを残して編集します。実在する情報だけを登録してください。お知らせ・作品・商品は初期状態では空です。空でも「準備中」と表示され、架空の実績や商品は掲載しません。

### お知らせの記入形式

以下は**記入形式の例**で、サイトには登録していません。日付・タイトル・説明を実際の情報に置き換えます。

```js
window.MOCHI_NEWS = [
  {
    date: '2026-10-15',
    title: 'ここに実際のお知らせのタイトル',
    description: 'ここにお知らせの内容',
    url: ''
  }
];
```

最新5件を日付の新しい順に表示します。`url` は空欄でも構いません。外部リンクは `https://` から入力します。

### ギャラリーの記入形式

```js
window.MOCHI_GALLERY = [
  {
    title: '実際の作品名',
    category: 'ドット絵',
    image: 'assets/images/your-art.png',
    alt: '画像の内容を説明する文章',
    description: '作品の説明'
  }
];
```

カテゴリは自動的に追加されます。画像をクリックすると拡大し、閉じるボタンまたはEscで閉じます。作品を追加する場合は `{ ... }` をカンマで区切って増やします。

### ゲーム・商品の記入形式

```js
window.MOCHI_GAMES = [
  {
    title: '実際のゲーム名',
    image: 'assets/images/your-game.png',
    description: 'ゲームの説明',
    status: '制作中',
    url: ''
  }
];
```

```js
window.MOCHI_SHOP = [
  {
    title: '実際の商品名',
    category: 'グッズ',
    image: 'assets/images/your-item.png',
    description: '商品の説明',
    url: 'https://販売先のURL'
  }
];
```

`url` が未設定なら販売・公開先は準備中として表示します。サイト内に決済機能はありません。

### SNS・プロフィール・画像

`data/site.js` の `socials` にURLをまとめています。Twitch・YouTube・Xは設定済み、FANBOX・BOOTHは空欄です。空欄のボタンはクリックできない準備中表示になります。

標準PROFILEの自己紹介は `profile.introduction`、画像は `profile.image` に指定します。文中の `\n` で改行できます。標準HOMEのメイン画像は `visuals.hero`、共通背景画像は `visuals.background` で変更できます。

画像ファイル名には半角英数字・ハイフンを使うと扱いやすくなります。パスの先頭に `/` を付けないでください。GitHub Pagesのプロジェクトサイトでは `/assets/...` は別の場所を指してしまいます。

### ビジュアル編集後も作品を追加できます

お知らせ・SNS・ギャラリー・ゲーム・ショップは「活動データ」のパーツとして取り込みます。これらは位置・サイズを編集でき、内容は上記データファイルに連動します。ギャラリーの絞り込みや拡大操作も維持します。

作品が増えて枠に収まらない場合は、パーツ内をスクロールして閲覧できます。スクロールを減らしたいときはエディターでパーツとページの高さを増やします。活動データ内部の詳細デザインは共通CSSで管理され、エディターのテーマ変更とは独立しています。

## GitHubへの反映と公開

リポジトリ：<https://github.com/mochi8989/mochimochi-site>

1. 念のため現在の `data/layout.json` をコピーしてバックアップします。
2. エディターで書き出したファイルを **`data/layout.json` に置き換えます**。ファイル名が `layout (1).json` になった場合は `layout.json` に変更します。
3. このフォルダで `node tools/build.mjs` を実行します。JSON、画像、HTMLの内部リンクを検査して `dist/` を生成します。
4. 次のコマンドでGitHubに反映します。

```powershell
git status
git add data/layout.json
git commit -m "Update website layout"
git push origin main
```

作品データや画像ファイルも変更した場合は、それらも `git add` します。画像をJSONに埋め込んだ場合はJSONだけで反映できます。

5. 初回はGitHubの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。
6. **Actions → Publish website → Run workflow** を選びます。公開処理が成功すると、通常は `https://mochi8989.github.io/mochimochi-site/` に表示されます。

**このワークフローは手動実行です。pushだけではサイトを公開しません。** 公開のタイミングを自分で決められます。初回公開・再公開の際に上記の「Run workflow」を実行してください。

### 編集画面を公開しない仕組み

公開ビルドはHTML・`assets/`・`data/` だけを `dist/` にコピーします。**`editor/`、開発ツール、Git情報は公開成果物に含めません。** GitHub Pagesにはこの `dist/` だけを送ります。

**Pagesの「Deploy from a branch / root」は選ばないでください。** それを使うと編集用ソースまで配信対象になります。上記のGitHub Actions方式を使用してください。

エディターはlocalhostでのみ動き、サイトからリンクしていません。ただしGitHubリポジトリ自体が公開の場合、編集ソフトのソースコードはリポジトリから読めます。これは非公開ログイン領域ではありません。パスワードや秘密の個人情報をファイルに入れないでください。

公開後もPCでエディターを起動し、保存済みJSONを開いて編集できます。公開サーバーに編集UI・書き込みAPI・認証情報を置く必要はありません。

参考：[GitHub公式：カスタムワークフローによるPages公開](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。公開リポジトリのGitHub PagesはGitHub Freeに対応しています。

### GitHubの認証が求められた場合

Git for Windowsの認証画面で **Sign in with your browser** を選び、`mochi8989` のアカウントで許可します。パスワードやトークンをREADME・チャット・ソースに書かないでください。

`Permission denied` / `403` の場合は、サインイン中のアカウントとリポジトリへの書き込み権限を確認します。GitHubアカウントの通常パスワードを `git push` のパスワード欄に入れても利用できません。

## フォルダ構成

```text
mochi-mochimochi-site/
├─ index.html, profile.html, gallery.html, games.html, shop.html, links.html
├─ page.html                 # 追加ページの公開表示
├─ widgets.html              # 更新データを表示するパーツ
├─ assets/
│  ├─ css/                   # 共通デザイン・JSONレイアウト
│  ├─ js/                    # 公開側の動作
│  └─ images/                # 画像とオリジナルSVG素材
├─ data/                     # 更新データ・編集結果のJSON
├─ editor/                   # ローカル専用ビジュアルエディター
├─ tools/                    # ビルド・ローカルサーバー・検証
├─ .github/workflows/pages.yml
├─ start-editor.cmd
├─ README.md
└─ dist/                     # 生成された公開用ファイル（Git管理外）
```

## 開発・検証

```powershell
node tools/build.mjs
node tools/serve.mjs 4173
```

公開用成果物は <http://127.0.0.1:4173/published/mochimochi-site/> で確認できます。そのURLの `editor/` は404になります。

導入済みChromeでの自動検証は `node tools/qa.mjs` です。Windowsの標準Chromeパスを使います。専用プロファイルとスクリーンショットはGit管理外の `.preview/` に保存します。実データの作品・商品や公開JSONをテストのために書き換えません。

`tools/create-site.py` は初期HTMLと素材の生成スクリプトです。通常の更新では実行不要です。実行すると標準HTML・初期SVGを再生成するため、それらを手で編集した後は上書きに注意してください。

## 素材・アクセシビリティ

クジラ・サメ・星空・メニューアイコンは、このサイト用に作成したSVGです。第三者のゲーム画像、キャラクター画像、外部フォントを使用していません。キャラクター・実作品の画像は所有者が後から登録する構成です。

標準ページはキーボード操作、スキップリンク、現在ページの表示、画像の遅延読み込み、OSの「動きを減らす」設定に対応しています。音声の自動再生はありません。ビジュアル編集したページでは、読み上げとTab移動の順序を表示位置に合わせます。画像の説明と文字のコントラストも編集時に確認してください。
